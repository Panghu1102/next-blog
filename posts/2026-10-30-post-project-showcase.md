今天，我对个人博客 `next-blog` 进行了一轮比较集中的更新。其中一个重要工作，就是为 **7 个 GitHub 项目建立独立的项目展示网站**。

以前，项目更多是通过 GitHub 仓库、README 或博客中的简单介绍来展示。随着项目逐渐增加，我希望能有一种更统一的方式，把项目背景、相关资料和仓库入口组织起来。因此，这次我把多个项目的展示页面整合进个人博客，为它们提供更完整的网页入口。

## 为 7 个项目建立独立页面

这次涉及的项目包括 JYACS、cfRelay，以及另外五个 GitHub 项目。

### 1. JYACS

JYACS 是这次项目网站建设中的一个重点。我将原有项目网站的内容重新组织到 `next-blog` 中，采用多页面的形式展示项目相关信息，而不是简单地把所有内容堆在一个页面里。

此外，我还调整了网站的动画效果、导航栏透明度和版本列表，让页面更统一，也方便访客查找不同类型的信息。

- 原项目网站：[jyacs.qzz.io](https://jyacs.qzz.io)
- [GitHub 仓库](https://github.com/Panghu1102/JYACS-web)
- [新项目页面](https://panghutech.com/zh/projects/JYACS)

### 2. cfRelay

cfRelay 同样获得了独立的项目展示页面。这次更新包括多页面内容组织、动画效果优化，以及博客项目列表中 cfRelay 展示入口的调整。

我希望它不再只是项目列表里的一条链接，而是能拥有自己的介绍空间，让访客在进入 GitHub 仓库之前，先了解项目的基本信息。

- [GitHub 仓库](https://github.com/Panghu1102/cfRelay)
- [项目页面](https://panghutech.com/zh/projects/cfRelay)

### 3. Real-ESRGAN-animevideov3

这个项目围绕动漫图像超分辨率相关技术展开。为它建立独立展示页面，可以把项目背景、技术方向和相关资料放在更清晰的结构中，降低访客了解项目的门槛。

### 4. panghu1102.github.io

[GitHub 仓库](https://github.com/Panghu1102/panghu1102.github.io)

这个仓库与我之前的 GitHub Pages 项目有关。通过在个人博客中建立独立页面，我可以为它提供一个更统一的展示入口，并将它与其他项目一起纳入个人网站的项目体系中。

这个项目与《苍之彼方的四重奏》及 GPT-SoVITS 相关方向有关。独立页面为项目提供了专门的展示入口，可以用于整理项目背景、相关技术方向和后续补充的资料。

### 6. SparkRelay

## 不只是新增页面：统一项目展示体验

这次工作的重点，并不是单纯地增加几个 URL，而是逐渐建立一套更完整的项目展示体系。

在实现上，我尽量复用共享的页面结构和数据驱动组件，减少不同项目之间重复编写页面的工作量，同时保留各个项目独立的内容与视觉风格。

这批页面也针对不同屏幕尺寸进行了适配，并通过动画改善页面切换与交互时的体验。未来有新的 GitHub 项目需要展示时，也可以沿用现有结构，而不必每次都从头搭建整套网站。

## 顺手完善 Sitemap 与 SEO

除了项目网站，我还修复了 `next-blog` 中的 Sitemap 生成逻辑。

此前，Sitemap 对部分页面的覆盖并不完整，不能充分反映网站实际拥有的内容。这次调整后，生成逻辑进一步覆盖项目页面、About 等标准页面，以及符合条件的博客文章。

我还调整了 Canonical 相关逻辑，将规范网址统一指向中文 `/zh` 页面，并排除 `/en` 路径，避免英文路径与中文规范页面之间产生不必要的收录冲突。

这些改动并不只是为了让 Sitemap 看起来更完整。对于搜索引擎而言，清楚地说明哪些页面应该被发现、哪些网址才是规范版本，同样是维护个人网站的重要工作。后续仍需要结合实际部署结果检查最终 Sitemap，确认新增页面确实出现在预期位置。

## 修复构建问题

在这轮更新过程中，我还处理了一个构建错误：代码引用了 `lucide-react` 中不存在的 `Github` 图标导出。修复后，我将相关图标替换为可用的 `Code2`，同时保留原有的 GitHub 仓库链接功能。

这个问题看起来很小，但在自动化部署环境中，一个图标导入错误就可能导致整个构建失败。因此，在持续增加功能的同时，及时处理构建问题也很重要。

## 接下来

这次更新让 `next-blog` 的项目展示体系向前迈进了一步：**7 个项目拥有了各自的展示入口，页面组织方式更加统一，网站的 Sitemap 和 Canonical 逻辑也得到了进一步完善。**

对我而言，个人博客不应该只是文章的集合，也可以成为自己开发过的项目、技术探索和实践成果的集中展示空间。

接下来，我还会继续完善各个项目页面的内容，检查实际部署效果，并逐步优化网站的可访问性、性能和搜索引擎收录表现。

项目不应该只有一个仓库地址。至少在我的个人网站里，我希望每个值得展示的项目，都能拥有一个属于自己的空间。
